## Summary in One Sentence

A Manifest V3 Chrome extension that captures selected text or full pages into three independently toggleable destinations (**Google Drive**, **Obsidian**, and **Local Markdown Files**). Social platforms (Facebook, Threads, X, Instagram, LinkedIn) use dedicated post extraction adapters (derived from upstream [PostSync](https://github.com/Joanna8521/PostSync)), while other websites run heuristic generic article extraction. The entire extension operates without intermediate servers; all network requests originate directly from the user's browser.

**Golden Rule**: Never edit `extension/manifest.json` or `extension/src/background.js` manually. Both are generated outputs of `python tools/build_manifest.py`.
- To modify permissions, OAuth client IDs, or content scripts, edit `extension/manifest.template.json`.
- To modify service worker logic, edit `extension/src/background.template.js`.

## Build Process (build_manifest.py)

```bash
cp .env.example .env
# Edit .env with your GOOGLE_OAUTH_CLIENT_ID and GOOGLE_OAUTH_CLIENT_SECRET
python tools/build_manifest.py
```

Running the script performs three tasks:
1. **Computes Stable Extension ID**: Calculates the Extension ID from the fixed `key` field (base64 public key) in `manifest.template.json` (SHA-256 first 32 hex chars mapped to `a-p`) and prints it. This ID is permanent across all machines, allowing a single OAuth Redirect URI registration to remain valid indefinitely.
2. **Generates manifest.json**: Replaces the `client_id` placeholder with the real value from `.env`.
3. **Generates background.js**: Replaces the `OAUTH_CLIENT_SECRET` placeholder with the secret from `.env`.

If `.env` is absent, placeholders remain untouched. Google Drive will display "Not configured", but Local Markdown and Obsidian remain fully functional.

### Why Client Secret is in background.js, Not manifest.json
This is a critical architectural decision. Early implementations attempted storing `clipvault_oauth_client_secret` as a custom top-level manifest key. While Chrome printed an "Unrecognized manifest key" warning, it appeared harmless at first glance.

However:
- Chromium forks (especially privacy-hardened variants like Comet) perform strict schema validation on `manifest.json`, actively stripping unrecognized keys.
- Consequently, `chrome.runtime.getManifest()` never contained the key, causing `clientSecret()` to return an empty string.
- Google OAuth token exchange (`grant_type=authorization_code`) strictly requires `client_secret` for Web Application client types, failing with `invalid_request: client_secret is missing`.
- Placing the secret in `background.js` (pure JavaScript) bypasses manifest schema validation completely.

### The Self-Referential Placeholder Substitution Pitfall
A subtle bug occurred when substituting strings: `build_manifest.py` replaced all occurrences of the placeholder across the file.

```javascript
// BUGGY INITIAL PATTERN:
const OAUTH_CLIENT_SECRET = 'OAUTH_CLIENT_SECRET_PLACEHOLDER';

function clientSecret() {
  return OAUTH_CLIENT_SECRET && !OAUTH_CLIENT_SECRET.startsWith('OAUTH_CLIENT_SECRET_PLACEHOLDER')
    ? OAUTH_CLIENT_SECRET
    : '';
}
```

Because `OAUTH_CLIENT_SECRET_PLACEHOLDER` appeared twice, both were replaced with the real secret. The condition became `secret.startsWith(secret)`, evaluating to `true`, and returning an empty string.

**The Solution**: Comparison checks match only a short distinct prefix (`REPLACE_ME`) rather than the full replacement string (`REPLACE_ME_WITH_YOUR_OWN_CLIENT_SECRET`):

```javascript
const OAUTH_CLIENT_SECRET = 'REPLACE_ME_WITH_YOUR_OWN_CLIENT_SECRET';

function clientSecret() {
  return OAUTH_CLIENT_SECRET && !OAUTH_CLIENT_SECRET.startsWith('REPLACE_ME')
    ? OAUTH_CLIENT_SECRET
    : '';
}
```

## OAuth Architecture (Authorization Code + refresh_token)

All authentication logic resides in `extension/src/background.template.js`:

| Function | Responsibility |
|---|---|
| `clientIdSet()` / `clientSecret()` | Validates whether placeholders have been configured |
| `launchAuthCodeFlow()` | First-time interactive authorization via `chrome.identity.launchWebAuthFlow()` |
| `refreshAccessToken(refreshToken)` | Background HTTPS POST to `oauth2.googleapis.com/token` without opening windows |
| `getToken(interactive)` | Unified entry: checks memory cache → attempts refresh_token → prompts interactive flow |
| `withAuthRetry(fn)` | Wraps authenticated API calls; clears cache and retries once on 401 |

### Why Not `chrome.identity.getAuthToken()`?
`chrome.identity.getAuthToken()` relies on Chrome's proprietary internal account bridge. Non-Google Chromium browsers (Vivaldi, Brave, Comet) do not implement this bridge. Using `launchWebAuthFlow()` ensures 100% compatibility across all Chromium browsers.

### Token Storage Strategy

| Token | Location | Reason |
|---|---|---|
| `access_token` | `chrome.storage.session` (`cvAuthToken`) | Short-lived; automatically purged when the browser or service worker restarts |
| `refresh_token` | `chrome.storage.local` (`cvRefreshToken`) | Long-lived; persists across browser restarts |

## Content Script Architecture

`extension/src/content.js` is the primary script injected into web pages, depending on three helper modules:
- `self.CLIP_VAULT` (`adapters.js`): Platform detection (`adapterFor(hostname)`)
- `self.CLIP_VAULT_EXTRACT` (`extract.js`): Structured data extraction (`extract()`, `outermost()`, `images()`)
- `self.CLIP_VAULT_GENERIC` (`generic-extract.js`): Generic web page extraction (`extractGeneric()`)

### Social Platforms (`ad` Present)
- **Post Detection**: `refreshPosts()` invokes `EX.outermost(ad, document)`. Triggered by `MutationObserver` (debounced 400ms) + capturing scroll listeners on `document`.
- **Memory Protection on Infinite Feeds**: When post count exceeds 120, retains only the closest 120 posts to the viewport vertical center, detaching distant DOM nodes and button listeners to avoid memory leaks.
- **On-Demand Reveal (Alt / Option Hover)**: Tracked via `triggerKey` (default `'alt'`). Buttons remain invisible until the user holds `Alt` while hovering over a post.
- **Windows Alt Focus Guard**: Pressing `Alt` in Windows Chrome normally focuses the menu bar and blurs the web page. Calling `ev.preventDefault()` on `ev.key === 'Alt'` preserves web page focus.
- **Facebook Multi-Photo Album Pagination (`collectAlbum`)**: Album posts with "+N" tiles hide photos outside the DOM. When enabled, temporarily opens the viewer, presses `ArrowRight` up to 30 times, and presses `Escape` to close the viewer while restoring original scroll coordinates.

### Generic Web Pages (`ad` Absent)
Uses a single floating button in the bottom-right corner. If text is selected, clips selection via `fromSelection()`. Otherwise, scores `<article>`, `<main>`, and content blocks via `mainCandidate()`.

## Implementation Details of the Three Destinations

### 1. Google Drive
- `resolveFolderPath(token, path)`: Recursively traverses and creates directory segments using `drive.file` scope.
- `createDoc()`: Creates a blank document and executes Docs API `batchUpdate` inserting title, metadata, canonical link, and body.
- `insertImages()`: Employs a two-tier fallback: direct URL insertion (`insertInlineImage`) → temporary Drive upload (`viaDrive()`) → markdown link list appendix.

#### Architectural Decisions: Why Not Google Picker?
1. **CSP Remote Script Restrictions**: Manifest V3 extension pages strictly forbid loading remote scripts (Picker requires `https://apis.google.com`).
2. **Sandbox Page CORS Block**: Sandboxed extension pages have a `null` origin, which Google's Picker backend actively rejects with CORS errors.
3. **Directory Path String Resolution**: Resolving paths programmatically under `drive.file` scope satisfies least-privilege standards without requiring external servers.

### 2. Obsidian
Constructs `obsidian://new?vault=...&file=...&content=...` and triggers it via a dynamic hidden anchor in the content script (`triggerObsidianUri()`).
- **Zero Tab Flicker**: Completely eliminates blank browser tab flashes.
- Safe URI length cap enforced at 6,000 characters with link fallback.

### 3. Local Markdown Files
Converts content to a base64 data URI (`utf8ToBase64()`) and calls `chrome.downloads.download({ url, filename, conflictAction: 'uniquify' })`.
- Omits global `onDeterminingFilename` listeners to avoid conflict errors with third-party download managers like IDM.

## Hard-Earned Lessons (Pitfalls to Avoid)

1. **Manifest Custom Keys Are Stripped**: Never store custom runtime configuration in `manifest.json`. Put them in JS modules.
2. **Self-Referential Placeholders**: Always use different prefix lengths when templating replacement tokens.
3. **Stale Service Worker Cache**: Extension reloads occasionally retain stale background workers. When troubleshooting stubborn caching issues, remove and re-add unpacked extension.
4. **Stable Extension ID**: Tied strictly to the `key` field in `manifest.template.json`. Do not change this key.
5. **Avoid Global Download Listeners**: Global `onDeterminingFilename` intercepts all browser downloads and crashes alongside IDM.
6. **Windows Alt Hijack**: Must call `ev.preventDefault()` on `Alt` keydown/keyup events to maintain web page focus.
7. **Hex-Escape Invisible Characters**: Always escape non-printable unicode characters in regex (`\u00AD`, `\x00-\x08`) so Git and grep do not classify code as binary.

## Common Maintenance Tasks

### Adding a New Social Platform Adapter
1. Add an entry to `self.CLIP_VAULT.ADAPTERS` in `extension/src/adapters.js` specifying `id`, `label`, `hosts`, `post`, `text`, `author`, and `more`.
2. `extract.js` is fully generic and rarely needs modification.
3. Verify that `manifest.template.json` includes the target host in `content_scripts.matches`.

### Adding a New Storage Destination
1. Implement `write<Target>(p, s)` in `background.template.js`.
2. Update `handleCapture()` with destination checks and try/catch blocks.
3. Add UI controls and storage bindings in `extension/options.html` and `options.js`.
4. Update storage schema tables in this document.

## Manual Testing Checklist

After making modifications to `content.js` or `background.template.js`, verify the following:

1. **Google Drive**: Connect Google → verify folder resolution → clip post → confirm Doc title, links, and inline images.
2. **Token Refresh**: Wipe `cvRefreshToken` in `chrome.storage.local` and confirm seamless re-authentication.
3. **Obsidian**: Confirm zero tab flashes and that note appears in Obsidian app.
4. **Local Markdown**: Confirm file downloads with correct title and clean layout.
5. **Platform Coverage**: Test regular text posts, expanded long posts, and multi-photo albums.
6. **Generic Web Pages**: Test selection clipping and full-page article extraction.
7. **Deduplication**: Re-clip same post twice and verify duplicate warning.
8. **Master Toggle**: Disable clipping in options and verify that all floating buttons detach cleanly.
